02 · 从单形态到多几何02 · one shape to six

六种形态
SPHERE → NOVA Six modes:
SPHERE → NOVA

单一球形太安静. 加了 5 种 GLSL 几何函数: DORMANT / VORTEX / PULSE / STORM / NOVA, 每种对应一个手势. 用链式 smoothstep 在几何之间连续插值。 A single sphere was too quiet. Added five GLSL geometry functions — DORMANT / VORTEX / PULSE / STORM / NOVA — one per gesture. Chained smoothstep blends between them.

颜色也随 vMode 走 6 段渐变. 每种形态有自己的色相 — SPHERE 冷蓝, NOVA 灼橙. Colour follows vMode across a 6-stop gradient — cold blue for SPHERE, blazing orange for NOVA.

04 · 最难的一段 · 让识别不抖04 · the hard part · stop the jitter

敌人不是准确率
是"抖" The enemy isn't accuracy —
it's jitter

MediaPipe 原始 landmarks 每帧都在轻微抖动. 直接映射到粒子上, 球看起来像帕金森. 花了三个版本处理这个: Raw MediaPipe landmarks jitter every frame. Piping them straight into the particles made the sphere look like it had Parkinson's. Three versions of work went into fixing this:

One-Euro Filter (minCutoff=2.5, β=0.15) per landmark, 左右手独立滤波状态; 三关节卷曲分数 (MCP+PIP+DIP 加权); per-finger 迟滞状态机; 防抖手势状态机 (candidate → stable 需要 GESTURE_ENTER_MS); 速度守卫 (手速 > 0.65 时追加 180ms 惩罚延迟)。 One-Euro Filter (minCutoff=2.5, β=0.15) per landmark, separate filter banks per handedness; three-joint curl score (MCP + PIP + DIP weighted); per-finger hysteresis state machine; debouncing gesture state machine (candidate → stable requires GESTURE_ENTER_MS); speed guard (an extra 180ms penalty when hand speed > 0.65).

Every layer I added made the sphere feel more like a real object.

测试的时候发现一个问题: 想仔细观察某个形态, 但手一动它就变了. 加了 LOCK 模式 — 双手全开 130ms 触发, 冻结形态和 openness. 锁定后 scale 仍然响应 (单手张合或双手距离), 方位继续跟随. 想看清楚就锁一下。 Testing revealed a problem: I wanted to inspect a specific mode, but every hand movement kept transforming it. Added LOCK mode — trigger with both hands fully open for 130ms. It freezes mode + openness, but scale still responds (single-hand pinch or two-hand distance), and rotation keeps following. Lock it when you want a proper look.

06 · 从"硬切"到"涌动"06 · from switch to swell

K=55 · D=14
弹簧阻尼 K=55 · D=14
spring dampers

最初形态切换用 lerp, 匀速插值 — 生硬得像 PPT 过场. 改成 K=55 / D=14 弹簧阻尼 (ζ≈0.94, 轻微欠阻尼), 加上 per-particle stagger (aRandom.z 偏移 ±0.15 mode 单位) 让粒子波浪式过渡. 视觉上, 从"切换"变成了"涌动"。 Originally mode transitions used lerp — constant-velocity, felt like a slide transition. Replaced with K=55 / D=14 spring dampers (ζ≈0.94, slightly under-damped), plus per-particle stagger (aRandom.z offset ±0.15 in mode units) so particles surge through the transition in waves. Visually: no longer a "switch," now a "swell."

uModeVel uniform 透传到 vertex shader, 转场期间叠加 churn noise displacement. 湍流量 transBoost 也跟弹簧速度挂钩 — 越快切换越剧烈。 uModeVel uniform is piped into the vertex shader; a churn-noise displacement kicks in during transitions. Turbulence transBoost is tied to spring velocity — faster switches, wilder churn.

Springs feel physical. Lerps feel like PowerPoint.

07 · 手指识别重构07 · finger recognition v2

双重确认
消除假阳性 Dual-check
kills false positives

最初用手腕做基点算手指角度 — 透视变形让假阳性满天飞: 手一转, 明明没伸的手指也判成"伸出". 重构: First implementation used the wrist as a base point for finger-angle calculation — perspective distortion produced false-positives everywhere: rotate the hand and closed fingers registered as "extended." Refactored:

移除 MCP 角度. 新增 fingerExtendedProj: 指尖投影到手掌轴 (旋转无关, 尺度归一化). 伸出判定: 角度 ≥ 2.40 且 投影 ≥ 0.30 (双重确认); 收回: 角度 < 1.65 或 投影 < 0.02 (任一触发). FIST 阈值收紧 openness < 0.22。 Dropped MCP angle entirely. Added fingerExtendedProj — fingertip projected onto the palm axis (rotation-invariant, scale-normalized). Extended = angle ≥ 2.40 AND projection ≥ 0.30 (both required); retracted = angle < 1.65 OR projection < 0.02 (either fires). FIST threshold tightened to openness < 0.22.

本地开发用 LaunchAgent 自动启 Python http.server (登录即运行, KeepAlive). 我的 Mac 一开机就是一台开发机。 Local dev is auto-managed by a LaunchAgent running Python's http.server (login-triggered, KeepAlive). My Mac boots straight into a dev environment.

Zero-cost + open-source + no login = the way the browser was supposed to work.

得到了什么? What was gained?

01

手势识别的敌人是"抖", 不是准确率 Gesture recognition's real enemy is jitter, not accuracy

MediaPipe 单帧准确率已经很高. 问题是相邻帧之间的抖动放大到粒子上, 整个球看起来像帕金森. One-Euro Filter + 滞后状态机, 才是让它"看起来在正常工作"的关键。 MediaPipe's per-frame accuracy is fine. The problem is frame-to-frame noise amplified into the particles — makes the whole sphere look diseased. One-Euro Filter + hysteresis state machines are what makes it look "normal."

02

浏览器 + 摄像头 = 世界上最便宜的 AR Browser + webcam = the world's cheapest AR

不装 APP, 不买眼镜, 不上传数据. 一切依赖都 CDN 加载, 一切计算都本地跑. 唯一硬件门槛 = 一台有摄像头的电脑。 No app install, no headset, no cloud upload. Every dependency loads from CDN, every computation runs locally. Hardware floor = one webcam-equipped device.

03

弹簧比 lerp 更接近"物理直觉" Springs read as physical, lerps read as PowerPoint

K=55 D=14 (ζ≈0.94) 就那么一小段过冲, 让形态切换从"UI 动画"变成"有质量的物体在动". per-particle stagger 是免费的波浪效果。 K=55 D=14 (ζ≈0.94) gives that little overshoot that makes a mode transition read as "a mass in motion" instead of "an interpolation." The per-particle stagger is a free wave.

04

零算力 = 无限访问 Zero server compute = unlimited reach

让访客的显卡付账, 我不需要担心访问量. 这是浏览器本来就该做到的事 — 只是大部分产品选择了云端推理是因为好收费。 When the visitor's GPU pays for compute, traffic is free. This is what the browser was designed for — most products just chose cloud inference because it's easier to monetise.
